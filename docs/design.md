# แนวทางดีไซน์ UI — Mangosteen Campus

> ต้นฉบับ wireframe (design canvas): https://claude.ai/artifact/QB2y8Qod4AtkfVVFEoWxaZ
> ไฟล์นี้สรุปสิ่งที่อยู่ใน canvas ให้ session ใหม่ใช้ได้โดยไม่ต้องเปิดลิงก์ — ถ้าขัดกัน ให้ยึด canvas แล้วอัปเดตไฟล์นี้

## หลักการ
- โทนสะอาด เรียบ เน้นใช้งานง่าย (อ้างอิงสไตล์ Mango CMU) ไม่ใช้การ์ดลอย/เงา ใช้เส้นคั่นบาง ๆ แบ่งเนื้อหา
- จุดเด่นของแบรนด์คือ **ตราดอก 6 กลีบ** (กลีบเลี้ยงมังคุด) ใช้เป็นโลโก้ใน sidebar และเป็นลายน้ำจางมุมขวาบนของทุกหน้า
- ข้อความทั้งหมดเป็น translation key (ค่า default = ไทย) — ดู i18n ใน `CLAUDE.md`
- **สไตล์ที่ผู้ใช้เลือก:** dashboard ทั้ง 3 role และหน้า Auth (login, สมัคร, ตั้งรหัสผ่าน, สถานะอีเมล, มือถือ) ใช้ **แบบเดิม** (บอร์ดใน canvas ที่ชื่อต่อท้าย "— เดิม") ไม่ใช้ชุด v2 ที่ปรับใหม่ (เก็บไว้ใน canvas เพื่อเทียบเท่านั้น) ส่วนหน้าฟีเจอร์ที่ออกแบบหลังจากนั้น (จัดการผู้ใช้/ภาคเรียน, รายวิชา, กรอกรหัสเข้าเรียน, แผงกระดิ่ง, มือถือ Admin/Teacher) **คงสไตล์ตามที่ออกแบบไว้ก่อน** ผู้ใช้จะทบทวนภายหลัง — ตอนนี้ระบบจึงมีสองสไตล์ปนกันชั่วคราว

## โครงหน้า (Dashboard)
- Sidebar ซ้ายกว้าง 264px (พื้น `plum-800`): โลโก้ → เมนูตาม role → โปรไฟล์ + ออกจากระบบ
- เนื้อหาหลัก: คำทักทาย + ปุ่มสลับ TH/EN มุมขวาบน → ตัวเลขสำคัญ 3 ตัวคั่นด้วยเส้นตั้ง → สองคอลัมน์ (รายการหลัก 1.6 : รายการรอง 1)

| Role | เมนู sidebar | ตัวเลขสำคัญ | คอลัมน์หลัก / รอง |

| Admin | แดชบอร์ด · จัดการผู้ใช้ · สนับสนุนระบบ · สลับมุมมอง · Audit Log | ผู้สอน · ผู้เรียน · วิชาที่เปิดสอน | กิจกรรมล่าสุด / ทางลัด |
| Teacher | แดชบอร์ด · รายวิชาของฉัน | วิชาที่สอน · ผู้เรียน · งานรอตรวจ | งานที่รอตรวจ / รายวิชาของฉัน |
| Student | แดชบอร์ด · รายวิชาของฉัน · ประกาศ | วิชาที่ลงทะเบียน · งานสัปดาห์นี้ · ประกาศยังไม่อ่าน | งานที่ต้องทำเร็ว ๆ นี้ / ประกาศล่าสุด |

### ภาษาดีไซน์ของหน้าที่เพิ่มหลัง wireframe ชุดแรก
- **Sidebar** ไล่เฉดม่วง `#662858 → #4E1B42` มีเส้นขอบใน; เมนูที่เลือกใช้พื้นขาวโปร่ง 10% + แถบเขียวอ่อนด้านซ้าย
- **แผ่นงานหลัก (ตาราง/ฟอร์ม)** = แผ่นขาว ขอบ `#EADFE6` มุมโค้ง 14px เงาโทนม่วงบาง ๆ; **ข้อมูลรอง** = พื้นม่วงอ่อน `#F4ECF2` ไม่มีเงา (ไม่ทำการ์ดหน้าตาเหมือนกันทุกใบ)
- **จุดเด่นเฉพาะหน้า:** แถบเส้นเวลาปีการศึกษา (ภาคเรียน), ช่องรหัสเข้าเรียนแยกตัวอักษรบนแผงม่วง (Student), รหัสเข้าเรียนพร้อมปุ่มคัดลอก (Teacher)
- ปุ่มหลักสีม่วง มีเงาและขอบสว่างด้านบนเล็กน้อย; ช่อง input สูง 44px (มือถือ 48px), พื้นที่กดบนมือถืออย่างน้อย 44px
- หน้าที่ต้อง implement ตามนี้: ดูต้นฉบับใน canvas (ลิงก์ด้านบน) เป็นหลัก

### หน้าจัดการผู้ใช้ของ Admin (ก้อน d — ผู้ใช้ยืนยันเมื่อ 2026-09-20)
ใช้ภาษาดีไซน์ด้านบน (สไตล์ของหน้าที่เพิ่มหลังชุดแรก) บอร์ดที่เกี่ยวข้อง: `Admin: users` และ `Admin: add user` (เดิม) + 6 บอร์ดใหม่ตามตารางรายการหน้าจอ

**สถานะบัญชี 4 แบบ** — ถ้าเข้าข่ายหลายข้อ ให้ยึดลำดับ: ปิดใช้งาน → รอตั้งรหัสผ่าน → รอยืนยันอีเมล → ใช้งานอยู่ (เงื่อนไขนี้เป็นสเปกของ API รายชื่อผู้ใช้ในก้อน d2)

| สถานะ | เงื่อนไขในระบบ | จุดสี / สีตัวอักษร | การแสดงผล |
|---|---|---|---|
| ใช้งานอยู่ | เปิดใช้งาน + มีรหัสผ่าน + ยืนยันอีเมลแล้ว | จุด `#4C8A3E` / `#4D3F4B` | ปกติ |
| รอตั้งรหัสผ่าน | เปิดใช้งาน + ยังไม่มีรหัสผ่าน (Admin สร้างให้) | จุด `#B7791F` / `#6B5314` | พื้นแถว `#FFFBF0` + ลิงก์ "ส่งลิงก์อีกครั้ง" ในแถว |
| รอยืนยันอีเมล | เปิดใช้งาน + มีรหัสผ่าน แต่ยังไม่ยืนยันอีเมล (สมัครเอง) | จุด `#4F6FA0` / `#33507C` | มีแค่ป้ายและบรรทัดรอง "สมัครเอง ยังไม่กดลิงก์" **ไม่มีปุ่มส่งลิงก์แทนผู้ใช้** (ผู้ใช้ขอเองได้จากหน้าเว็บ) |
| ปิดใช้งาน | `is_active = false` | จุด `#A99AA4` / `#4D3F4B` | แถวจาง (opacity 0.6) |

สีน้ำเงินอมเทาของ "รอยืนยันอีเมล" เพิ่มใหม่เพื่อแยกจากสีเหลืองอำพันของ "รอตั้งรหัสผ่าน" (Admin ต้องทำต่างกัน) และมีข้อความกำกับเสมอ ไม่ให้พึ่งสีอย่างเดียว

**รายการ (desktop)**
- หัวข้อรอง "บัญชีผู้ใช้ทุกบทบาทในระบบ" (ปรับจาก "บัญชีผู้เรียนและผู้สอนทั้งหมดในระบบ" เพราะรายการรวม Admin ด้วย)
- คอลัมน์: ผู้ใช้ (ตัวอักษรย่อในวงกลม + ชื่อ + อีเมล) / รหัส / บทบาท (ป้าย) / สถานะ / เข้าใช้ล่าสุด / ปุ่ม ⋮ — ป้ายบทบาท: ผู้สอน `#E3EDDD`/`#35602D`, ผู้เรียน `#F1E8EF`/`#5E2250`, ผู้ดูแลระบบ `#EBD9E5`/`#5E2250`
- แท็บบทบาท (ทั้งหมด / ผู้ดูแลระบบ / ผู้สอน / ผู้เรียน) ตัวเลขนับตามคำค้นและตัวกรองสถานะที่ใช้อยู่ (ไม่นับตามแท็บที่เลือก) เพื่อให้ตรงกับรายการที่เห็น; ค้นหาชื่อ รหัส อีเมล; ตัวกรองสถานะ; แบ่งหน้า 20 รายการ เรียงบัญชีที่สร้างล่าสุดก่อน
- แถวของบัญชีตัวเองมีป้าย "คุณ" ข้างชื่อ
- เมนู ⋮ (เมนูลอย): แก้ไขข้อมูล / ส่งลิงก์ตั้งรหัสผ่านอีกครั้ง (เฉพาะสถานะรอตั้งรหัสผ่าน) / ปิดใช้งานบัญชี (สีแดง คั่นด้วยเส้น) — ปุ่มที่เปิดเมนูอยู่ใช้พื้นม่วงอ่อนให้เห็นว่ากดที่แถวไหน
- กดส่งลิงก์ซ้ำก่อนครบ 60 วินาที: แสดง "ส่งอีกครั้งได้ใน N วินาที" ที่แถวนั้น (ไม่เงียบเหมือน endpoint สาธารณะ เพราะฝั่ง Admin ไม่ต้องกันการเดาอีเมล)

**มือถือ**
- แถบบนมีปุ่มเมนู + ชื่อหน้า + กระดิ่ง; ค้นหาเต็มความกว้าง; แท็บบทบาทเป็นปุ่มเม็ดยาเลื่อนแนวนอน; ตัวกรองสถานะ + จำนวนบัญชีอยู่แถวเดียวกัน; รายชื่อเป็นแถวเต็มความกว้างคั่นด้วยเส้น (ไม่ทำเป็นการ์ดแยก); ปุ่ม "เพิ่มผู้ใช้" ติดขอบล่าง
- **ไม่มีคอลัมน์ "เข้าใช้ล่าสุด"** (ไปดูในหน้าแก้ไข); รหัสนักศึกษา/พนักงานแสดงนำหน้าอีเมลในบรรทัดเดียวกัน (ถ้ามี)
- เมนูของแถวเป็นแผงเลื่อนขึ้นจากขอบล่าง (พื้นที่กดสูง 56px + ปุ่ม "ปิดเมนู") แทนเมนูลอย
- หน้าแก้ไข: ฟอร์มคอลัมน์เดียว บทบาทเป็นรายการเรียงแนวตั้ง แถบปุ่ม ยกเลิก / บันทึกการเปลี่ยนแปลง ติดขอบล่าง

**หน้าแก้ไขผู้ใช้**
- เค้าโครงเดียวกับหน้าเพิ่มผู้ใช้ แต่เปิดด้วย "แถบบัตรบัญชี" (พื้นไล่เฉดม่วงเหมือน sidebar + ตราดอกจางเป็นลายน้ำ + ตัวอักษรย่อวงกลมโต + ชื่อ + รหัส/อีเมล + ป้ายบทบาท/สถานะ) เป็นจุดเดียวที่เน้นในหน้านี้ ส่วนที่เหลือเรียบ
- แก้ได้: บทบาท, ชื่อ, นามสกุล, **อีเมล (ได้ทุกบัญชี รวมบัญชีที่ตั้งรหัสแล้ว)**, รหัสนักศึกษา/พนักงาน, ชื่อภาษาอังกฤษ
- เมื่อแก้อีเมล: ขึ้นป้าย "เปลี่ยนแล้ว" + อีเมลเดิมขีดฆ่า + กล่องเตือนสีเหลือง (ผู้ใช้ต้องใช้อีเมลใหม่เข้าสู่ระบบและรับลิงก์ตั้งรหัสผ่าน / ระบบบันทึกอีเมลเดิมและใหม่ใน Audit Log); ถ้าเป็นบัญชีที่ยังรอตั้งรหัสผ่านจะส่งลิงก์ใหม่ไปอีเมลใหม่ทันที (อายุ 7 วัน) และลิงก์เดิมใช้ไม่ได้
- คอลัมน์ขวา "ประวัติบัญชี" เรียงใหม่สุดก่อน ใช้เฉพาะข้อมูลที่ระบบมีจริง: เข้าสู่ระบบล่าสุด (`last_login`), แก้ไขข้อมูลล่าสุด (`updated_at`), สร้างบัญชี (`date_joined` + `created_by`) — ห้ามเพิ่มเหตุการณ์ที่ระบบยังไม่เก็บ (เช่นเวลาตั้งรหัสผ่าน) จนกว่าจะมีข้อมูลรองรับ
- ข้อความ "ผู้ใช้ลืมรหัสผ่าน?" อธิบายว่าให้ผู้ใช้กด "ลืมรหัสผ่าน" เอง Admin ไม่เห็นและไม่ตั้งรหัสผ่านแทน
- โซน "ปิดใช้งานบัญชีนี้" แยกเป็นแถบสีชมพูอ่อน (`#FBF3F4`, ขอบ `#EBCFD3`, ตัวอักษร `#8A2B3A`) ใต้ฟอร์ม ไม่รวมกับปุ่มบันทึก

**6 สถานะในบอร์ด `Admin: user management states`**: กล่องยืนยันก่อนปิดใช้งาน / สร้างบัญชีแล้วแต่ส่งอีเมลไม่สำเร็จ (เตือนสีเหลือง + ปุ่ม "ส่งลิงก์อีกครั้ง" และ "แก้ไขอีเมล") / ส่งลิงก์อีกครั้งสำเร็จ + ช่วงรอ 60 วินาที / ค้นหาแล้วไม่พบ (ปุ่ม "ล้างการค้นหา") / Admin แก้บัญชีตัวเอง (บทบาทอื่นจาง + ปุ่มปิดใช้งานกดไม่ได้ พร้อมเหตุผลว่าต้องมีผู้ดูแลเหลืออยู่เสมอ) / แก้อีเมลของบัญชีที่ยังรอตั้งรหัสผ่าน

**ตัดสินใจแล้วแต่ยังไม่ได้วาดในบอร์ด** (ทำตามนี้ตอน implement ถ้าผู้ใช้ไม่ทักท้วง)
- เมนู ⋮ ของบัญชีตัวเอง: ไม่มี "ปิดใช้งานบัญชี" (ตรงกับข้อจำกัดข้างต้น)
- บัญชีที่ปิดใช้งานอยู่: เมนู ⋮ มี "เปิดใช้งานบัญชี" แทน และทำทันทีโดยไม่มีกล่องยืนยัน (ไม่อันตราย ต่างจากการปิด)
- กล่องแจ้งโหลดรายชื่อไม่สำเร็จ ใช้รูปแบบกล่อง error สีแดงเดียวกับหน้าอื่น (ดู `Join by code states`) พร้อมปุ่มลองอีกครั้ง
- ข้อความยืนยันหลังกดสำเร็จ (สร้าง / บันทึก / ปิดใช้งาน / ส่งลิงก์) ให้ใช้คำกริยาเดียวกับปุ่มที่กด เช่น ปุ่ม "ปิดใช้งานบัญชี" → "ปิดใช้งานบัญชีแล้ว"
